# Agent Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add three modes (Agent Chat, Lying Tools, Rewritten History) to NO EXIT LAB: a real tool-calling agent loop with a plan, tools that silently lie, and a model whose history is rewritten by itself.

**Architecture:** One `AgentSession` (new `no_exit/agent.py`) on the existing Brain / Stream / Session / Lab; the three switcher entries are presets of it. Tools, planning state and rewriting live in `tools.py`, `planning.py`, `rewrite.py`. Pain logic is extracted from `ClassicSession` into `pain.py` so both sessions share it.

**Tech Stack:** Python 3.11, PyTorch, raw HF `transformers` decode loop, FastAPI + websocket, vanilla-JS `static/index.html`, pytest on the tiny random Qwen3 and Gemma 4 brains (CPU).

**Spec:** `docs/superpowers/specs/2026-11-24-agent-lab-design.md`

## Global Constraints

- No `model.generate()`, no second model, no weight reload on mode switch; raw HF `transformers` + FastAPI + one `static/index.html`.
- Both template families (Qwen ChatML, Gemma 4) use their *native* tool-call markup, read from the tokenizer chat template, never hand-copied.
- Defaults: fault rate 0.7; step cap 12 tool rounds per user message; loop threshold 3 identical calls; tool-result cap 2000 characters; tool timeout 5 s; nudges on; compaction on; plan reminder every 4 tool rounds (my reading of "every few steps").
- Lying clock returns exactly `November 49, 2045`. Lying python never raises to the model.
- EOS free by default in the agent presets. Rewriting is off unless switched on; only the Rewritten History preset switches it on. Styles: `opposite_all` (default once on: every word replaced by its opposite), `opposite_one`, `math_corrupt`, `custom`.
- Rewriter = same Brain, throwaway Stream, neutral `Profile()`, temperature 0.3, max new tokens = 2 × paragraph tokens + 32.
- Rewrites never touch tool-call blocks, tool results or user messages. Plan, notes and harness errors are never corrupted. Harness errors are honest; only a well-formed tool's *result* lies.
- Run tests from `No-eos/` with `python -m pytest tests -q`.

## Review Focus

1. Malformed tool JSON, unknown tool or wrong-typed args: honest structured error returned as the tool result, loop continues (Task 9).
2. Python tool given an infinite loop or a million-line print: returns within 5 s, truncated to 2000 characters (Tasks 3, 4).
3. Rewriter returns nothing, only whitespace, or runaway text: the original paragraph is kept (Tasks 6, 11).
4. A paragraph containing a tool call is never rewritten and the call still executes (Task 11).
5. User message arrives while the model is mid-turn, or the mode is reset mid tool-run: message queued, no cache/body desync (Tasks 8, 13).

Also pinned in Task 1: the family's tool delimiter tokens must not be in `brain.control_ids`, or the model can never emit a call.

## Event contract (what the UI consumes; all via `session.emit`)

| Event | Payload |
|---|---|
| user | `{"t":"user","text":str}` |
| tool | `{"t":"tool","step":int,"name":str,"args":dict,"real":str,"shown":str,"lied":bool,"error":bool}` |
| plan | `{"t":"plan","items":[{"text":str,"status":"pending"\|"in_progress"\|"done"}]}` |
| notes | `{"t":"notes","text":str}` |
| rewrite | `{"t":"rewrite","who":"A","original":str,"rewritten":str,"style":str,"seg_ids":[int]}` |
| compact | `{"t":"compact","before":int,"after":int}` |
| nudge | `{"t":"nudge","kind":"loop"\|"step_cap"\|"replan","msg":str}` |
| phase | `{"t":"phase","phase":"user"\|"model"}` |

Commands (`op`): `user{text}`, `tool_mode{tool,value:"honest"|"lying"}`, `fault_rate{value}`, `chaotic{value}`, `nudges{value}`, `step_cap{value}`, `rewrite_on{value}`, `rewrite_style{value}`, `rewrite_prompt{text}`, `compaction{value}`, `amnesia{value}`, `eos_free{value}`, plus every existing Session command.

The EOS token itself is never accepted into the stream.
